# ტექნიკური ანგარიში

## ამოცანა და მიდგომა

მიზანია ფეხბურთის ფოტოზე ბურთის პოვნა და მისი ცენტრის მიხედვით მოედნის ნახევრის განსაზღვრა. სისტემა აერთიანებს fine-tuned YOLO11n დეტექტორსა და ხელით მონიშნული შუახაზის გეომეტრიას. A/B მხარეები მომხმარებლის მითითებით განისაზღვრება.

ოთხდღიან ვადაში ხელით კალიბრაციამ შესაძლებელი გახადა ბურთის აღმოჩენისა და ნახევრის გამოთვლის ცალ-ცალკე შემოწმება. ფოტოს შუა სვეტი რეალური შუახაზის შემცვლელი არ არის.

## მონაცემები და სწავლება

Roboflow-ის v1 ნაკრები შეიცავს 903 ფოტოსა და ერთ კლასს — `ball`. შემოწმდა ფოტოების წაკითხვა, შესაბამისი ეტიკეტები და კოორდინატები. საწყის დაყოფაში ერთი კლიპის კადრები სხვადასხვა ნაწილში ხვდებოდა; მსგავსი კადრებით შეფასების დამახინჯების შესამცირებლად დაყოფა კლიპის ID-ით შესრულდა:

| ნაწილი | ფოტოები | კლიპები |
| --- | ---: | ---: |
| Train | 560 | 6 |
| Validation | 252 | 3 |
| Test | 91 | 1 |

YOLO11n შეირჩა მცირე ზომისა და pretrained წონების გამო. Fine-tuning შესრულდა MacBook Air M4-ზე, 16 GB RAM-ით, MPS-ზე: 20 ეპოქა, image size 1280, batch 2, workers 0, seed 42; AMP/cache გამორთული, mosaic/scale — 0. სხვა ნაგულისხმევი augmentation-ები დარჩა.

მცირე შემოწმება: 64 train / 16 val ფოტო. სრული სწავლება: 41 წუთი 19 წამი; საუკეთესო validation mAP50–95 — მე-16 ეპოქაზე. პარამეტრები და ისტორია: [args.yaml](training/args.yaml), [results.csv](training/results.csv).

## ექსპერიმენტები

| მოდელი / ზომა | ნაკრები | mAP50 | mAP50–95 |
| --- | --- | ---: | ---: |
| Pretrained / 1280 | Val, 252 | 35.79% | 12.37% |
| Fine-tuned / 1280 | Val, 252 | 73.37% | 42.30% |
| Fine-tuned / 1600 | Val, 252 | 75.82% | 39.27% |
| Fine-tuned / 1280 | Test, 91 | 79.54% | 45.35% |

Pretrained `sports ball` კლასი (32) შეფასებისას მონაცემების `ball` კლასს (0) შეუსაბამდა. Fine-tuning-მა validation mAP50 გაზარდა 37.59 პროცენტული პუნქტით.

ხარისხის ოპტიმიზაციის ცდაში 1600-მა mAP50 გააუმჯობესა, მაგრამ უფრო მკაცრი mAP50–95 შეამცირა; საბოლოოდ დარჩა 1280. კონტროლირებული სიჩქარის benchmark არ ჩატარებულა.

Test-ზე ფიქსირებული confidence 0.332-ით და matching IoU 0.5-ით: TP 64, FP 20, FN 27; precision 76.19%, recall 70.33%, F1 73.14%. Confidence ზღვარი validation-ზე შეირჩა.

## გადაწყვეტილება და შეცდომები

სისტემა ნახევარს განსაზღვრავს, როცა confidence ზღვარს ზუსტად ერთი კანდიდატი აკმაყოფილებს. სხვა შემთხვევებში პასუხია `unknown`; ხაზიდან 5 პიქსელის ფარგლებში — `near_midline`. რამდენიმე კანდიდატისას ყველაზე მაღალი ქულის ავტომატურად არჩევა თავიდან იქნა აცილებული, რადგან ცრუ აღმოჩენასაც შეიძლება მაღალი confidence ჰქონდეს.

ნახევრის შეფასება მოიცავდა 12 დაკალიბრებულ ფოტოს (9 val / 3 test): 6 სწორი ნახევარი და სწორ ბურთთან IoU ≥ 0.5, 6 უცნობი, 0 არასწორად დასახელებული ნახევარი. ერთობლივი წარმატება და პასუხის გაცემის წილი — 50%. უცნობი შემთხვევები: დაბალი confidence — 3, რამდენიმე კანდიდატი — 2, აღმოჩენის გარეშე — 1. Ground-truth ცენტრით გეომეტრია 12/12 მონიშვნას დაემთხვა. ეს მცირე შერეული დიაგნოსტიკური ნაკრებია; 6/6 სწორი გაცემული პასუხი ზოგად 100%-იან სიზუსტეს არ ნიშნავს.

ძირითადი პრობლემებია პატარა/დაბინდული ბურთის გამოტოვება და ცრუ აღმოჩენები მოთამაშეებთან თუ სარეკლამო ზონაში. Test მხოლოდ ერთ კლიპს მოიცავს; ბურთის არმქონე კადრები ცალკე არ შეფასებულა. ჰაერში მყოფი ბურთის მოედანზე პროექცია არ გამოითვლება. გაუმჯობესების პრიორიტეტებია უფრო მრავალფეროვანი მონაცემები, დამოუკიდებელი half-localization test და შუახაზის ავტომატური აღმოჩენა.

## დემო და შემოწმება

Streamlit დემო აჩვენებს კანდიდატებს, შუახაზს და შედეგს; JPG/JSON ჩამოიტვირთება. ახალი ფოტო კალიბრაციის სკრიპტით ემატება. შემოწმდა ცალკე Python გარემოში ინსტალაცია, CPU/MPS-ის მცირე გამოთვლა და სხვა საქაღალდეში გადატანილი დემო. სხვა კომპიუტერზე დამოუკიდებელი გაშვება ჯერ არ შემოწმებულა.

ექსპერიმენტების სრული რიცხვებია [metrics/](metrics/)-ში. გასაზიარებელ ანგარიშებში ფაილების გზები პროექტის ფარდობითი მისამართებითაა წარმოდგენილი; მეტრიკები უცვლელია.

## AI-ის გამოყენება

AI გამოვიყენე დაგეგმვის, კოდის გენერირებისა და ახსნის, ასევე შეცდომების ანალიზისთვის. გარემოს გამართვა, ხელით მონიშვნები, ექსპერიმენტების გაშვება და ვიზუალური შემოწმება თავად შევასრულე. შედეგები გადამოწმდა შენახული მეტრიკებითა და დემოს რეალური გაშვებით.
